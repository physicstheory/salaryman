# Salary Man, as a desktop application

The engine is `Web/konto.html` — one file, Three.js, no build step. This folder
is the shell that turns it into something you install: a window with no browser
chrome, a real fullscreen key, the libraries vendored so it starts with no
network, and a private `konto://` scheme so the page has an origin and can fetch
the character model.

```
Game/
  main.js            the Electron main process: window, protocol, keys
  preload.js         almost nothing on purpose
  tools/stage.js     copies Web/konto.html in and points it at vendor/
  vendor/            three.js r128 and GLTFLoader, so a launch needs no internet
  build/icon.png     Soti Tower at dusk
  app/               generated by stage.js, not in git
  dist/              generated by electron-builder, not in git
```

## Running it

```
npm install
npm start
```

Ctrl+R reloads after an edit to `Web/konto.html`, F11 is fullscreen, F12 opens
the developer tools.

## Building an installer

```
npm run dist:win      # NSIS installer and a portable exe
npm run dist:linux    # AppImage
npm run dist:mac      # dmg
```

Cross-building Windows from Linux needs Wine; the GitHub Actions workflow builds
each on its own runner instead, which is simpler and what the released builds
come from.

## Why a custom protocol

Loaded from `file://` a page has an opaque origin, so `fetch("seiko.glb")` is
refused and the character never arrives. The usual answer is to turn web
security off, which turns it off for everything. Serving the staged folder over
`konto://` gives the page an ordinary secure origin and leaves every other
protection where it was.

## What is not signed

Nothing. Windows SmartScreen will warn the first time a build runs, and macOS
will refuse one outright without an Apple developer certificate. Signing is a
paid certificate and an annual renewal, and until there is a reason to pay for
one the builds stay unsigned.
